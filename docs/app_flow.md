# Application Flow

This document outlines the core user journey and application flow for initial onboarding and usage. Follow this flow when developing features related to onboarding and navigation.

## 1. Registration
- **Screen**: Registration Page
- **Action**: User registers using their Email, Password, and Confirm Password.
- **Next Step**: Upon successful registration, the user is redirected to the Login page.

## 2. Login
- **Screen**: Login Page
- **Action**: User logs in with their credentials (Email and Password).
- **Next Step**: The system checks tenant status:
    - If **No Tenant** (Tenant does not exist), redirect to the Tenant Creation step (`/create-tenant`).
    - If **Tenant Exists**, proceed directly to the Main Dashboard (`/(main)`).

## 3. Tenant Creation
- **Screen**: Create Tenant Page
- **Condition**: User has logged in but has no associated tenant workspace.
- **Action**: User provides details to create a new tenant organization/workspace.
- **Automated Provisioning**: Upon creation, the system automatically provisions 4 default operational shifts:
    1. **Morning Slot**: 06:30 AM – 11:00 AM (Breakfast prep, early tea, morning snacks)
    2. **Afternoon Slot**: 11:00 AM – 03:30 PM (Heavy lunch prep, peak lunch rush, dining cleanup)
    3. **Evening Slot**: 03:30 PM – 07:30 PM (Evening snacks, shift crossover)
    4. **Night Slot**: 07:30 PM – 11:30 PM (Dinner prep, late dinner service, closing & deep cleaning)
- **Next Step**: User is immediately redirected to the Main Dashboard (`/(main)`), bypassing manual shift setup.

## 4. Default Operational Shift Management
- **Description**: Default operational shifts are pre-configured upon workspace creation. Users can view or edit operational shifts under Workspace Shift Management settings anytime.

## 5. Day Tracking & Counter Cash Management
- **Screen**: Main Dashboard / Day Control Modal
- **Condition**: When a Manager logs in or accesses the dashboard.
- **Rules**:
  - **Start Day**: A day must be active/started for operations. When starting the day, the Manager inputs the initial **Opening Counter Cash**.
  - **Running Operations**: Transactions, POS sales, and ledger entries run under the active day with automated shift detection based on time.
  - **End Day**: At the end of business operations, the Manager executes **End Day** and inputs the final **Closing Counter Cash** for daily financial reconciliation.
  - **Resume Day**: If ended within the same calendar date, a day can be resumed/reopened if necessary before final closing.

## 6. Main Dashboard
- **Screen**: Home Page / Main Layout
- **Condition**: Reached immediately after tenant creation or login.
- **Action**: The user can access the full functionality of the application, manage business days, and monitor live sales.

## 7. Terminal Device Flow
This flow describes the setup and usage of secondary terminal devices (e.g., POS or kiosk devices).

### 7.1. Admin Adds Terminal Device
- **Screen**: Admin Dashboard (Terminal Management)
- **Action**: Admin user adds a new terminal device.
- **Constraint**: The **Name** of the device is mandatory.
- **Tenant Device SL**: Each device automatically receives a sequential Serial Number (`device_sl`, e.g. SL #1, SL #2) auto-incremented per tenant workspace.
- **Fixed Unpair Code**: Upon pairing, a fixed 6-digit **Unpair Code** is generated for the device. This code is visible ONLY to Admins/Owners on the Admin Dashboard.
- **Immediate Device Removal**: Admins can remove/disconnect any paired device from the Admin UI. Upon removal, the device is deleted immediately, revoking access so the device is instantly logged out and returned to the pairing screen on its next request.

### 7.2. Terminal Device Login & Unpairing
- **Screen**: Terminal Pairing/Login Page
- **Action**: The terminal device pairs by entering the 6-digit pairing PIN generated by the Admin.
- **Unpairing Device**: To unpair a terminal device directly from the kiosk, the operator must enter the 6-digit **Unpair Code** assigned to that device.
- **Next Step**: Once successfully paired, the terminal displays the **Staff List**.

### 7.3. Staff Login & Terminal Operations
- **Screen**: Staff Selection Page & Terminal Dashboard (on the Terminal)
- **Action**: A staff member selects their profile from the staff list and logs in.
- **Business Day Enforcement**:
  - The system checks if an active **Business Day** is running.
  - If no business day is active (started), the terminal prompts/enforces the user (or Manager) to **Start Day** with Opening Counter Cash before POS or ledger operations can be performed.
- **Next Step**: Once an active day is confirmed, the staff member proceeds to the **Homepage/Terminal Dashboard** to execute sales and transactions.
